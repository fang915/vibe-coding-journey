# 发布前检查 · Pre-release check

## 这个 Skill 干什么

回答一个问题：**「现在这个状态，能不能发布？」** —— 不靠感觉，靠 16 条带数字的判据。
每条给出实测值和四级结论之一：

| 状态 | 含义 | 计入通过？ |
|---|---|---|
| FAIL | 违反判据，发布级问题 | 否，**阻断发布** |
| WARN | 不阻断，但发布前该看一眼 | 否，单独计数 |
| PASS | 实测达标 | 是 |
| **SKIP** | 这条**没查**（网络不通 / 缺依赖），写明原因 | **否，绝不冒充通过** |

最后一行汇总是「通过 X ／ 阻断 Y ／ 提示 Z ／ 未检查 S」。**Y > 0 → 退出码 1**，可以直接当门禁。
本 Skill 不替你修任何东西，只报告。

## 什么时候用

- 发布之前（重传静态托管、重贴云函数之前跑一次）。
- 拿不准「我改的这些东西是不是漏了什么」的时候。

## 什么时候不用

- 改一行文案就想确认页面样子 —— 用 `filter-interaction-check` 或直接看页面更快。
- 想接成自动化流水线 —— **Day 25 明确不做**，脚本本身可当门禁，但本项目暂不接 CI。

## 怎么执行

```bash
"C:/Users/方/.workbuddy/binaries/node/versions/22.22.2-3/node.exe" \
  "D:/桌面文件/vibe coding实战/skills/pre-release-check/scripts/check-release.mjs" \
```

- 不加 `--browser` 时跳过「真实渲染」那一条（其余照跑，`render` 记 SKIP）。
- `--out` 指定 HTML 报告（`report.html`）与机器读数（`last-run.json`）的输出目录；不指定则写到 Skill 根目录。
- `--skip-live` 只跑离线部分（断网时用，公网三条会记 SKIP）。

要看懂 HTML 报告，用无头 Edge 截图即可（整页）：
`node skills/pre-release-check/screenshots/../../../..` —— 直接参考 `USAGE.md` 里的截图方法，
或用本机任意截图工具。报告页无外部依赖，`file://` 或本地静态服务都能打开。

## 16 条判据（四层）

### 第一层：仓库卫生

| 判据 | 通过标准 | 级别 |
|---|---|---|
| `git-clean` | `git status` 无未提交改动 | 提示 |
| `git-sync` | 本地 HEAD == `origin/main`（`git ls-remote` 实测） | 阻断 |
| `env-ignored` | `.env`、`tests/admin-token.txt` 被 `.gitignore` 覆盖且未被跟踪 | 阻断 |

### 第二层：密钥

| 判据 | 通过标准 | 级别 |
|---|---|---|
| `secret-scan` | 61 个已跟踪文件里，7 类模式 0 命中（`sk-`、`AKID`、私钥块、`X-Admin-Token` 实值、超长 Bearer、带口令连接串、硬编码密钥赋值）；命中值**打码后**展示 | 阻断 |

### 第三层：工程正确性（离线，随时可跑）

| 判据 | 通过标准 | 级别 |
|---|---|---|
| `js-syntax` | 全部 `.js`（不含 `deploy/`）过 `node --check` | 阻断 |
| `offline-tests` | `tests/api-shape.test.js` 失败 0 项，且通过数 ≥ 基线 105 | 阻断 |
| `svg-xml` | 所有 `.svg` 可被 XML 解析（Day 24 的静默坑） | 阻断 |
| `cjk-encoding` | 12 个中文文件 UTF-8 严格解码、无 U+FFFD、无乱码片段 | 阻断 |
| `deploy-mirror` | `deploy/` 内 8 个文件与源码 SHA256 一致 | 阻断 |
| `version-drift` | 见下节「版本基线机制」 | 阻断 |
| `asset-refs` | 必备文件齐全 + `index.html` 本地引用 0 处 404 | 阻断 |
| `docs-claims` | README 声称的菜数 == `data/dishes.json` 实际条数 | 提示 |

### 第四层：公网真实状态

| 判据 | 通过标准 | 级别 |
|---|---|---|
| `live-static` | 线上 `index.html` 200、关键词在、全部引用资源 200、与 `deploy/` 副本字节一致（不一致 → WARN「线上落后」） | 阻断 |
| `live-api` | `/api/dishes` 200、结构对、404 文案是双语人话且无技术原文；条数与本地兜底不同 → WARN | 阻断 |
| `live-favicon` | 声明的 `favicon.svg` 线上 200。**明确不查 `/favicon.ico` 的 404** —— 页面声明了 svg 图标后浏览器默认探 `.ico` 得 404 属正常现象，查了就是假警报 | 阻断 |
| `render`（`--browser`） | 无头 Edge 真实加载公网站点：缩略图全部有解码宽度、横向溢出 0px、判定段控制台错误 0 条 | 阻断 |

## 版本基线机制（`version-drift`）

要防的问题只有一个：**内容改了、`?v=` 没升 → 用户拿到旧缓存**。

- 脚本在 `state/version-baseline.json` 里记每个资源的「SHA256 + 当时版本号」。
- 内容没变 → 刷新记录；内容变了且版本号也变了 → 正常升版，更新基线；
  **内容变了但版本号没变 → 保留旧基线，持续报 FAIL**，直到改回内容或升版本号。
- 这个「保留旧基线」很重要：如果每次跑都无脑覆盖基线，故障态会被下一轮洗白，检查就虚了。
- 首次运行没有基线 → 全部记为「首次记录」，只建账不报警。

## 真实渲染那一条的口径

- 无头 Edge 连 CloudBase 测试域名会先撞「风险提醒」中间页：按钮 **3 秒倒计时禁用**，
  点早了被 `if (submitBtn.disabled) return` 无声忽略。脚本等 `#submitBtn` 解除禁用再派发鼠标事件。
- **中间页自己会产生 2 条 404**（那一次 Document 404 + 它自己的 `/favicon.ico` 404），
  这是腾讯云测试域名的行为，不是本站的毛病。脚本只判定「过闸门之后」的加载，
  被排除的条目会**明示**在报告里（「另排除闸门期 N 条：…」），不偷偷吞掉。

## 报告格式

终端一张表（状态 / 检查项 / 实测值），外加 `report.html`（浅色、无外部依赖、可整页截图）与
`last-run.json`（给程序读）。**每条都有实测数字，不许写「看起来正常」。**

## 这套判据自己被校准过的痕迹（重要）

Day 25 实跑时，第一版判据出了 2 个 FAIL，查证后**都是判据自己在误报**，已改：

1. ~~「所有 `?v=` 必须相同」~~ → 本项目四个资源的版本号本来就各不相同，且各自与该文件
   最后一次改动对得上（css/app.js 是 Day 24、data-source 是 Day 20、router 是 Day 13）。
   按「必须相同」判会把正常状态判红。改成上面的「版本基线」机制。
2. ~~「探针 id 用 `__not_exist_for_check__`」~~ → 格式非法的 id 会被接口判 **400**（那是 400 的职责），
   根本轮不到 404 文案。探针 id 必须合法格式但库里没有（`no-such-dish-for-check`）。
3. ~~「控制台错误必须是 0 条，无论来源」~~ → 中间页自己会制造 404，见上节口径。

**教训：检查工具喊狼来了和虚报通过一样糟糕。判据每出一次红，都要先审判据，再修代码。**

## 不查什么

- 不查内容准确性（菜的历史说法对不对）—— 那是内容核实的活。
- 不查移动端、不查性能（加载速度）、不查 SEO。
- 不替你部署、不替你修复。它只报告「能不能发」。

## 出岔子怎么办

| 症状 | 处理 |
|---|---|
| `git-sync` 记 SKIP | 网络抖动（github.com 间歇 reset），重跑；或先 `git ls-remote` 手动确认 |
| `render` 记 SKIP | 调试端口没起来：上次没退干净时换 `--user-data-dir`，或重跑 |
| `version-drift` 一直报同一个文件 | 要么把内容改回去，要么正式升版本号（两处：`index.html` 的引用 + `deploy/index.html`） |
| 报告页打不开 | 报告是纯 HTML，直接双击也能开；路径含中文时用本地静态服务打开更稳 |
| SVG 校验记 SKIP | 本机没有配置里的 Python 路径 —— 检查 `check.config.json` 的 `browser.pythonPath` |
