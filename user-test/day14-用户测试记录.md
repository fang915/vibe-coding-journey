### 0.2 开发者自查：手机到底适不适应？（2026-10-01 实测）

用真机参数（390×844、DPR 2、移动端 UA）无头渲染线上版本，量「文档实际宽度 − 视口宽度」，
结果**和第一印象不完全一样**：

| 页面 | 320px 宽 | 360px 宽 | 390px 宽 |
|---|---|---|---|
| 首页 `#/` | 0 溢出 ✅ | 0 溢出 ✅ | 0 溢出 ✅ |
| 地区索引 `#/regions` | 0 溢出 ✅ | 0 溢出 ✅ | 0 溢出 ✅ |
| 地区列表 `#/region/guangxi` | 0 溢出 ✅ | 0 溢出 ✅ | 0 溢出 ✅ |
| **卡片页 `#/dish/luosifen`** | **溢出 345px** ❌ | **溢出 305px** ❌ | **溢出 275px** ❌ |

- 溢出即「手机上一屏装不下，右边的内容被推到屏幕外，得横向滑动才看得见」。
- 卡片页在最窄的 320px 上，文档宽 **665px —— 是屏幕的两倍多**。
- 越界元素全是 `<a>`（宽 604 / 421 / 303 / 280px）—— 进一步把元素的**文本打出来**才定位到真凶：
  **卡片底部「出处 / Sources」列表里的长网址**，例如
  `http://www.liuzhou.gov.cn/sjzt/zxzt/zwzt/dlfzsfjj/lsfcyfz/202412/t20241220_3567476.shtml`。
  网址是连续无空格的字符串，浏览器默认不肯断行，一条就 604px 宽，把整页顶开了。
- ⚠️ **排查教训（第一版猜错了）**：最初把矛头指向「面包屑太长」—— 实测面包屑本体宽 **350px**、
  `scrollWidth` 也是 **350**，完全清白。**别按「哪块文字看起来最长」猜，要把越界元素里的文本打出来看。**
- **为什么连开发者本人也没发现**：很可能只看了列表页和目录页（那三页确实是好的），
  或者打开了卡片页但没意识到右边被切——因为中文段落自动换行，看着「挺自然」，
  不像坏了，只是**最右边那一小条内容悄悄消失在屏幕外**。

## 1. 给测试者的任务卡

### 开场话术（照念，**一个字都不要多说**）

> "我在做一个讲中国菜的网站，想请你帮我试试能不能用。
> 这三个任务没有标准答案，你怎么弄都行。我不会教你 ——
> 你遇到问题就用你自己的办法解决。
> **过程中请把心里想的话说出来**，想到什么说什么，这对我最有帮助。"

### 观察者三条铁律

1. **不提示、不解释、不辩解。** 他说"这怎么没有搜索框"，你也别指给他看。
2. **不问他"你觉得好不好看"。** 这种问题只会得到客气话，测不出东西。
3. 他卡住**超过 60 秒**，才可以问一句"你现在在想什么？"——问完就闭嘴。

### 任务 1 · 找到一道菜

> "你想了解一下广西的**螺蛳粉**。请用这个网站找到它的页面。"

**重点看**：他第一眼看屏幕的哪里？是先发现搜索框，还是先去翻地区目录？用了多久？

### 任务 2 · 按地区翻

> "假设你想知道**山西**有什么好吃的。请用这个网站找出来，并告诉我山西收录了什么菜。"

**重点看**：他找得到"按地区浏览"那个入口吗？在目录页找到山西之后，他知不知道那张卡是可以点的？

### 任务 3 · 读懂一张卡片，并分享（附加要求：**只看英文**）

> "随便打开一道你没听过的菜，看完告诉我它在讲什么。
> **这一步请你假装看不懂中文，只看英文部分。**
> 然后把这道的名称和链接发给我。"

**重点看**：不看中文，他读得懂吗？他找得到"复制"按钮吗？粘贴出来的内容对不对？

## 4. 结论与最小修复（板块③ 填写）

### 4.1 先把观察摊开排队

| 观察（原话 / 行为） | 猜测的原因 | 候选修法 | 是最小可行改法吗 |
|---|---|---|---|

| "总体而言还是很流畅的" | 打开、点按无阻塞 | 无需修 | — |
| "页面会适应手机屏幕大小" | 首页 / 索引 / 列表三页实测 0 溢出，与开发者本人的感受一致 | 无需修 | — |

### 4.2 选定要修的那一个

挑选标准（**三条同时满足**才算数）：

- [x] 记录里有**直接证据**（同机实测的数字：文档 665px vs 视口 320–390px）
- [x] 改动**局限在一处**（只动了一条 CSS 规则）
- [x] 改完我能**实测证明**它好了

**要修的是：出处里的长网址撑破手机布局**

- **改前现象**：任意一道菜的详情页，在 320 / 360 / 390px 三种手机宽度下，文档宽都是 **665px**，
  比屏幕宽出 275–345px。右侧约半屏内容被推到屏幕外、必须横向滑动才看得见 ——
  连出处列表里的第 3～6 条来源都直接消失在屏幕外。

- **改了什么（文件 + 位置）**：
  - `css/style.css` 第 789–798 行，`.sources a` 规则加两行：
    `overflow-wrap: anywhere;`（标准写法）+ `word-break: break-word;`（老浏览器兜底）。
    **只动了这一条规则，别的一行没碰。**
  - `index.html` 里 4 处 `?v=` 版本串 `20260929b` → **`20261001a`**。
    （改 CSS 必须同步推版本串，否则浏览器只认旧 URL、继续用缓存里的旧样式。）

- **改后验证（怎么测的、看到什么）**：
  - 同一套 CDP 真机参数（390×844 / DPR 2 / `mobile: true`）重扫四个页面 × 三档宽度：
    首页 / 地区索引 / 地区列表 / **卡片页 —— 全部 0 溢出** ✅
  - 卡片页 `scrollWidth` 从 **665 → 390**，与视口一致。
  - 截图对比（图片存在同目录 `screenshots/`）：改前 `screenshots/src-before-online.png` 里 `http://www.liuzhou.gov.cn/sjzt/...` 被右边缘生硬切掉；
    改后 `screenshots/src-after-local.png` 里 6 条出处**全部完整折行显示**。
  - 桌面端（1280px）复测一遍，出处列表渲染正常，**没有改坏原有的样子**。

### 4.3 本次不修的（写清为什么，别默默跳过）

- **「缺乏设计感」** —— 说话人**没指明具体是哪一处**：配色、留白、卡片长得雷同、还是缺图片？
  四种答案对应完全不同的改法。而且整体视觉翻新属于**大改版**，今日清单把它明确列为「今日不做」。
  → 先追问拿到落点，记进下一步计划。
- **出处里「直接显示完整网址」这件事本身** —— 604px 的长串即使折行了也并不好看，
  更理想的写法是只显示域名 + 标题、网址放进 `title` 或省略号中间截断。
  但这属于**改设计**，不是「最小修复」的范围。→ 记进下一步计划。
- **7 道菜还没有配图** —— 已知状态（不是本次反馈带来的问题），单独排期处理。
