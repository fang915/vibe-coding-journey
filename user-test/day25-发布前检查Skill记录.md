## 建 Skill 过程中，判据自己被校准的三次

这一天的真功夫在**审判据**上 —— 检查工具喊狼来了和虚报通过一样糟：

1. ~~所有 `?v=` 必须相同~~ → 实跑 FAIL，但 git 历史证明四个版本号各自与文件最后一次改动
   对得上，**判据误报**。换成「版本基线」机制：内容变了版本号没升才报，且保留旧基线持续报警，
   故障态不会被下一轮洗白。
2. ~~404 探针 id 用 `__not_exist_for_check__`~~ → 接口判 400（格式非法归 400 管，轮不到 404 文案）。
   探针 id 必须合法格式但库里没有。
3. ~~控制台错误必须 0 条~~ → 探针查明那 1 条是腾讯云测试域名**中间页自己的 404**
   （一次 Document 404 + 它的 `/favicon.ico` 404）。改成只判「过闸门之后」的加载，
   排除项在报告里明示（另排除闸门期 2 条），不偷偷吞掉。

## 今日一问

**问：你故意弄坏哪一项来验证 Skill 不会虚报通过？**

答：三项，分别落在三个层 —— ①把一条硬编码口令写进 `js/app.js`（安全层）；
②改了 `css/style.css` 的内容但不动版本号（发布卫生层）；③只改 `deploy/` 镜像不改源码（交付一致性层）。
第 1 次实跑：三处全被抓住（`secret-scan` 精确到 `js/app.js:1517` 且把口令打码、`version-drift`
点名文件和它卡住的版本号、`deploy-mirror` 列出不一致的文件），退出码 1，报告结论是「现在不要发布」。
第 2 次把三处还原再跑：0 阻断、退出码 0。**一红一绿都对得上，才说明它不是一台永远亮红灯或永远绿灯的机器。**
另外还有一层「不虚报」：网络不通时相关项记 SKIP 并单独计数，绝不冒充通过；报告里被排除的读数（闸门期 404）也明示出来。
