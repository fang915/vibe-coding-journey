## 1. 为什么"重复"才算检测

单次走通只能说"这一次行"。重复检测要回答的是另外两个问题：

1. **数字会不会漂**（卡片数、条数、正文长度、事实/出处条数）—— 漂了说明有竞态或缓存问题；
2. **状态会不会残留** —— 上一轮的搜索结果/筛选条件有没有带到下一轮去。

所以每一轮都**重新加载页面**（带一个唯一查询串 `?day28r=N#/` 强制真刷新，不是只改 hash），
依次走试用卡里的四步：**首页 → 搜索 → 地区筛选 → 详情滑到底**。

## 2. 方法（可复现）

- 脚本：`tools/day28-flow-repeat.mjs`（本次新增，纯 Node 零依赖）
- 浏览器：无头 Edge + CDP（`--headless=new`、零缓存 profile、视口 1180×1000）
- 命令：`node tools/day28-flow-repeat.mjs 3`
- 原始数据：`user-test/day28-flow-repeat.json`（每轮每一步的实测值都在里面）

两个关键写法（第一版没写，导致 3 次假绿，见 §5）：

1. **等"真数据到手"再读**：`index.html` 里预置了 5 张静态兜底卡（无 JS 也能看），
   所以"列表里有卡片"不等于"接口数据到了"。判据改成等页脚状态栏 `data-source="api"`。
2. **等下家渲染完再读**：读数字前先把要读的 DOM 清成哨兵值（`__pending__` / 清空 `innerHTML`），
   否则上一轮残留的 DOM 会"立刻满足"等待条件，读到的其实是上一道菜的数字。

## 4. 附加探针：搜索词没清空就直接点地区（probeB）

真人很可能这么点：搜到螺蛳粉、看完卡片、点「返回 / Back」、顺手点「福建」。

| 观察项 | 实测 |
|---|---|
| 返回首页后搜索框内容 | 仍是「螺蛳粉」（设计如此，不自动清空） |
| 点「福建」后卡片数 | **0** |
| 空态标题 | 没找到这道菜 · Nothing found |
| 空态正文 | 「福建」里没有匹配「螺蛳粉」的菜。换个说法，或点下面的按钮看全部。 · No match for "螺蛳粉" in 福建 |
| 「看全部」按钮 | 可见、可点 |
| 点「看全部」之后 | 回到 `#/`，**13 道全部回来** |

**结论：这是 Day 12 定下的设计行为（关键词 + 地区取交集），不是 bug** ——
关键在于它**说清了是哪两个条件叠加**、并且**给了一条出路**（看全部按钮）。
探针 `explainsBothConditions` 与 `recoverable` 均为 true。

> 同一现象在 Day 21 的复核里被误当过一次"探针脏"（当时搜的是"披萨"，地区筛选出 0 结果）。
> 今天把它当成一条正式路径测过一遍，结论一致：文案与出路都在，不需要改。

## 5. 诚实记录：第一版脚本的 3 次假绿（问题在脚本，不在站点）

这块留着，因为它正是今天复盘那句话的素材：**看着绿了不算，得知道绿是从哪来的。**

| 轮次 | 症状 | 根因 | 修法 |
|---|---|---|---|
| 第 1 版 | 第 1 轮首页读出 5 张卡，误判失败 | 读到的是 `index.html` 里的**静态兜底卡**（JS 还没把接口数据画上去） | 等待条件改成 `data-status[data-source="api"]` |
| 第 1 版 | 搜索步读出卡名是「菜名」（模板占位文字） | 只等了 hash 变化，没等详情渲染 | 加一步：等 `#card-name-zh` 真的变成「螺蛳粉」 |
| 第 2 版 | 第 2、3 轮详情步读到的仍是上一轮的螺蛳粉数字 | 等待条件被**上一轮残留的 DOM** 立刻满足 | 读之前把卡片页清成哨兵值，再点、再等新渲染 |

三次修完，第 3 版 3 轮全绿且数字一致 —— 这个"绿"才有分量。
